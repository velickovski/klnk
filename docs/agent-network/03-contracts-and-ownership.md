# Frozen integration interfaces

27 October 2026. Root owns shared domain schemas, database migration/backup/delete integration, API registration/validation, App navigation, dependencies and final evidence. The source candidate from the previous product remains historical and immutable.

Use `packages/domain/src/network.ts` for all internal v1 shapes. No invented phone contacts. Server worker modules use `network/store.ts`: `NetworkStore.in(sql).get/list/put/remove` with encrypted payloads and immutable record ownership. Every mutation locks active participant owner rows in lexical order through `lockNetworkOwners` **before** record writes. Shared reads require explicit participant membership. Private policy/memory records have only ownerA. Never return the peer's policy or private memory.

Coordination worker owns `network/coordination.ts`, `network/policy.ts`, `tests/network-coordination.test.ts` and its report. Calendar worker owns `network/calendar.ts`, `features/network/CalendarPanel.tsx`, `tests/network-calendar.test.ts` and its report. Panel worker owns other `features/network/*` panels and tests/report. Root owns `features/network/api.ts` and contracts. Next wave independent QA owns new network QA/E2E files and evidence.

`InternalCalendar(db)` exports `available(sql, ownerIds, slot, excludingEventId?)`, `commit(sql, conversation, proposal, acceptances, policies, connection)`, `list(owner)`, `cancel(owner,eventId,revision)`, `dismissReminder(owner,id)`. Commit runs inside the caller's already owner-locked transaction, independently rechecks current records/authority/hash/availability, returns `NetworkEvent`, and writes event/reminders/outbox idempotently. `NetworkCoordinator(db, calendar)` exports identity(owner), invite(owner,memberCode), connections(owner), updateConnection(owner,id,input), policy(owner), savePolicy(owner,input,expectedVersion), memories(owner), saveMemory(owner,input,id?,version?), deleteMemory(owner,id), submit(owner,input), inbox(owner), detail(owner,id), decision(owner,id,input), control(owner,id,action), markRead(owner,id), tick(), start(), stop(). Background tasks are network records, separate from legacy jobs. Tick processes bounded atomic steps with stable owner locks; no provider transport.

UI panels receive `ownerId` and use the root-owned typed `networkApi`; identity remount clears their state. Root will integrate tabs/navigation. No worker edits shared files without a transferred lease. Tests use fictional members and no real provider requests. Reports state exact commands/results and gaps, never production self-certification.
