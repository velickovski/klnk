# Typed owner intent bridge

27 October 2026. Changed `apps/server/src/network/owner-intent.ts`, `tests/network-owner-intent.test.ts` and optional `scripts/network-model-smoke.ts`. Root owns routes, wire/UI integration and the coordinator's guarded-submit extension.

`OwnerIntentService(db, coordinator, {apiKey, fetch?})` exposes `execute(owner,{commandId,text})`, `read(owner,commandId)` and `confirm(owner,commandId,planHash)`. Its exported `OwnerIntentResult` has `commandId`, `status` (`clarification`, `draft`, `submitted`, `processing`, `uncertain` or `failed`), and optional `clarification`, `plan`, `planHash`, actual `conversation`, and sanitized `reason` code. Submitted means persisted in the internal coordinator; the returned conversation's state remains the execution evidence.

The model receives one owner's current scheduling policy, server time and accepted-member names/opaque identifiers. It receives no peer policy, private memory, calendar contents or previous model conversation. Full-name/member-code ambiguity is resolved before paid planning. One stateless `gpt-6.1-sol` Responses POST uses `store:false`, no tools, strict JSON Schema, at most 2,000 output tokens, low reasoning, a 30-second timeout and redirects disabled. Runtime domain/schema/scope validation follows Structured Outputs; refusal, incomplete output, malformed output, unexpected tool calls, invented connections and expired/out-of-scope plans fail without effects.

An encrypted owner-only receipt records the source command, private keyed argument digest and claim before a paid call. Exact repeated command UUIDs recover status; changed instructions conflict. Unknown paid outcomes are durable and never automatically retried. After 35 seconds a still-planning receipt can become unconfirmed; late model output cannot then acquire authority. Concurrent planners deduplicate under owner row locks. A separate current-policy/connection guard inside the coordinator transaction prevents a model plan from gaining authority during a post-planning race.

Routine meeting commands submit automatically only within the owner's current explicit autonomous grant and scheduling bounds. Other model-generated plans remain exact drafts for personal confirmation. The exact local `Tell FULL NAME that MESSAGE` parser can submit faithful information without a model call when a single configured topic and current message scopes apply. That path grants no meeting authority. No model-generated message is silently treated as the owner's exact wording. Plans persist before internal submission, and readback resolves actual immutable request state after a lost response. Public results exclude source audit text, provider bodies and credentials.

OpenAI Docs skill references fetched on this date before implementation: [GPT-6.1 Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol), [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), and [Responses API guidance](https://developers.openai.com/api/docs/guides/migrate-to-responses). These support the chosen model, `text.format` strict schema, stateless storage selection and output/refusal handling. API access remains account-dependent.
