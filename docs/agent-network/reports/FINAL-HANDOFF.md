## Implemented behavior

Versioned internal schemas/records are separate from phone-required telephone missions. Migrations007/008 preserve old records; no phone contact is fabricated or promoted into a member connection. The new workspace contains summary-first Inbox, internal Calendar, real member People, private Memory and scoped autonomy/privacy/voice Settings. Earlier requests/adapters remain under an explicit compatibility entry and `legacy=1` browser fixtures.

Opaque member codes link immutable registered account IDs. Invitations, accepted connections, directional inbound permission, mute/block and revision checks govern routing. Default autonomy is off. Each owner independently selects trusted members, topics/actions, permitted facts, working hours/timezone, duration/notice/window, expiry and automatic routine acceptance. A login token is never reused as the other owner's background identity.

Durable owner-bound tasks process while the recipient client is offline. Every disclosure and commit rechecks active accounts, connection and current policy revisions/expiry. Incoming text is data and cannot grant tools or authority. Only explicitly selected confirmed, shared, unexpired recipient facts may be projected; neither agent receives the other's private policy, full calendar or memory. Coordination is bounded deterministic rule/slot processing, not a synthetic telephone conversation or an unverified claim that two live language models negotiated.

Meetings use immutable canonical proposals, hashes and acceptance records. Sorted database owner-row locks serialize shared schedules across processes/connections. Current authority/terms/availability are independently checked at commit, which writes one event, own reminders and outbox atomically. Routine acceptance is attributed to the agent's rule; authenticated exact-proposal human approval has its own receipt. An explicit original request/approval may make a timing exception, while model voice submissions cannot grant themselves an exception. Pending, expired, paused, declined and agreed remain distinct. Only the relevant recipient is asked when routine timing/automatic acceptance is insufficient. A message never creates a meeting. Cancellation updates the shared result/reminders; material changes require a new proposal/request.

Natural-language typed planning uses one stateless, bounded, server-side OpenAI request with own limited context. Permitted routine meetings can submit automatically; other model text stays an exact inspectable draft. Exact `Tell FULL NAME that MESSAGE` preserves the owner's message without a model rewrite when current scopes allow it. Durable command claims prevent duplicate paid planning; unknown results do not automatically retry. Lost results use the same identifier, readback and an explicit same-instruction resend if the first request never reached the server. Required voice permissions are three explicit tools; voice uses the established documented browser transport and returns structured actual state. New live audio semantics were not tested in this pivot.

Notifications/reminders are internal durable items, available on return. They do not prove that a closed app alerted someone. Owners can select decisions/results/quiet notices and shared retention7/30/90 days. Terminal shared records use the shorter owner setting after a past event ends; future events/pending decisions survive. Hourly retention, account deletion and backup deletion-journal reconciliation remove related shared records and scrub cached owner-command text/plans, preserving only non-content retry bindings. Reads/replays of removed instructions return410 rather than claiming submission. This repair was independently exercised.

## Release status and scope limits

This is a functioning local candidate, **not production or native-iPhone certification**. Native Live still needs a documented Expo58/RN0.88-compatible transport, Apple/Expo signing, a compatible macOS/Xcode build environment or explicitly authorized EAS build, and physical iPhone microphone/audio/route/interrupt/background tests. VoiceOver, Voice Control, Switch Control, native text scaling, notifications, human listening/usability and representative-device performance remain unrun. The three high dependency findings and public identity/onboarding/recovery, production key custody/rotation, monitoring/budgets, continuous deletion journal/PITR and rollout/review/privacy archive gates remain open.

Version1 supports internal information, permitted-context questions, meetings and their own reminders. Arbitrary new task obligations, external-calendar awareness, device-calendar sync, APNs/email/SMS, financial actions and purchases are unavailable. Rescheduling is a fresh request rather than a silent shared edit. The bounded English exact-message parser and natural-language interpretation are not a multilingual/ASR quality guarantee. Browser secure UUID/credential behavior does not prove native storage support. Private server/model processing is disclosed and is not end-to-end encrypted or offline.

No real-person call, external message, external calendar mutation, marketing communication, deployment, cloud build, signing resource or App Store submission was performed. PostgreSQL test fixtures are stopped and their disposable namespaces removed; normal local preview services remain running. Source candidate files are `.data/release-candidate/klnk-agent-network-2026-10-27.json` and `.zip`, with an independently checked `.verification.json`. They exclude credentials, databases, dependencies and generated bundles. The exact configured-secret scan is limited evidence, not a general security certification. The previous candidate archive remains historical and unchanged.
