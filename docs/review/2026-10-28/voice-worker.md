# M2 Voice worker implementation report

Owner: `/root/security` on the subsequent Voice card. Work started only after the M1 snapshot `14e706c` was pushed. This report does not independently approve this worker's own changes.

## Implemented files

- `apps/server/src/network/recorded-voice.ts`: actual server-side `gpt-transcribe` multipart transcription followed by owner-intent processing. Durable owner-bound metadata reserves each recording before the provider request. Same-ID replay never retranscribes; altered recordings conflict. Limits are one active recorded turn, 60 starts per day and a 2 MiB decoded upload. An unresolved continuous Live conversation blocks another recorded voice start. Transcription failures never become invented words or audio.
- `apps/server/src/network/recorded-voice-routes.ts`: authenticated status, POST turn and GET same-turn receipt routes. The actor/session is created from the HTTP bearer and rechecked inside owner-lock transactions. POST uses a 3 MiB JSON body ceiling and six requests/minute through the shared limiter. Independent QA caught missing production TLS/origin enforcement on this new path; it now reuses the Live HTTPS/exact-Origin guard, with authenticated native no-Origin requests allowed over HTTPS. The registration requires the app's configuration as its third argument.
- `apps/server/src/network/owner-intent.ts`: a trusted server-only `requireInformationReview` option, bound into the retry digest. Native recorded messages first become exact drafts. A separate recording saying “Send this exact request” confirms the current command/hash through the existing authorization path; model-provided confirmation fields are not accepted. Deterministic exact information defaults to topic `message` without autonomy setup. Plain questions/messages can be prepared independently of automatic meeting/answer rules. Meeting and connection operation epochs preserve a plan across unrelated reminder or mute edits while still fencing material authority changes.
- `apps/server/src/openai-live.ts`: authenticated `/voice/live/status` and owner lifecycle access beyond localhost. Production requires HTTPS, trusted proxy configuration and exact permitted browser origins. Native authenticated clients can omit Origin. The standalone legacy demo remains local-only. The existing durable owner/day/global limits, controller leases, unresolved-session barrier and 300-second duration cap remain in force. Production starts require a bearer; the shared reservation receives its hash for a fresh credential check.
- `apps/mobile/src/features/live/browser-live.ts`: explicit authentication before capture; removed anonymous `/auth/demo` account creation and credential adoption. Product readiness uses the authenticated status endpoint. Existing uncertainty/closure and identity-change cleanup remain.
- `apps/mobile/src/features/network/NativeVoicePanel.tsx`: real bounded capture using the installed `expo-audio` hook, OpenAI transcription, and actual Expo device speech reading the server's reply verbatim. It uses Expo Crypto UUIDs and the shared session data client. It reads all proposed candidate intervals, material terms, recipient and expiry before exact confirmation. Listening resumes after device playback ends, with a pause while a queued agent result is polled and then narrated from canonical state. Background/unmount stops capture/playback; each session has a five-minute cap. Unknown starts keep the original identifier, force fresh GET readback, and allow an explicit same-recording retry only after a 404. No paid retry is automatic.
- `apps/mobile/src/voice-io.native.ts`: an observed-recording latch discards an interrupted capture rather than submitting a partial recording; the existing 30-second capture limit and local file deletion remain.
- Regression files: `tests/network-recorded-voice.test.ts`, `tests/openai-live-production.test.ts`, `tests/network-owner-intent.test.ts`, `tests/openai-live.test.ts`, `apps/mobile/test/voice-live.test.ts`.

## Native/API research and remaining gates

Current official [GPT-Live WebRTC](https://developers.openai.com/api/docs/guides/voice-webrtc) and [session creation](https://developers.openai.com/api/reference/resources/live/methods/create) document the trusted server SDP broker used here. They do not document a GPT-Live ephemeral-client-secret endpoint. The similarly named `/realtime/client_secrets` belongs to the **different Realtime API**; it was not invented or silently substituted for GPT-Live.

Current [file transcription](https://developers.openai.com/api/docs/guides/speech-to-text) recommends `gpt-transcribe`. The [Speech API](https://developers.openai.com/api/docs/guides/text-to-speech) models are deprecated with a January 2027 shutdown, so a new deprecated cloud TTS dependency was avoided. The recorded fallback honestly uses [Expo Speech](https://docs.expo.dev/versions/latest/sdk/speech/) `~58.0.3`, matching the installed SDK's bundle map, and [Expo Crypto](https://docs.expo.dev/versions/latest/sdk/crypto/) `~58.0.7`. Device speech may be inaudible in iPhone Silent Mode; the screen discloses that. Playback completion is not proof the user heard a reply.

The maintained [WebRTC config-plugin matrix](https://github.com/expo/config-plugins/blob/main/packages/react-native-webrtc/README.md) currently documents versions only through Expo 56. The OpenAI-linked [Switchboard toolkit](https://github.com/switchboard-sdk/openai-live-toolkit#before-you-ship) additionally says its relevant native builds are private and its WebRTC build needs a local SDK. Neither provides verified Expo 58 / React Native 0.88 compatibility for this project. No such SDK was installed. Native Live remains gated; the opening must use the recorded fallback through the orchestrator's navigation integration.

Still required: independent HTTP/component QA after integration, final Expo export/browser journeys, real OpenAI model-account access and listening checks, iOS signing/build, physical iPhone capture/playback/routes/interruption tests, assistive technology and latency evidence. Continuous Live information/question tools retain their M1 owner-review gate; the fully spoken exact readback/confirmation implemented here is the recorded native path. Recorded clarification asks for a complete updated instruction rather than pretending to maintain an unimplemented arbitrary conversation history. Multi-instance live controller maps still require the M4 work; broker HTTP tests do not establish a multi-instance deployment.

Independent voice QA also identified the duration-limit boundary: native capture stops at 30 seconds, but the server does not parse a submitted media file's duration. A direct authenticated client can submit longer compressed audio within the 2 MiB upload ceiling. Server provider-spend bounds are currently bytes, daily starts and active turns, not a verified 30-second media duration. Enforcing server media duration requires actual supported-media parsing or transcoding; a client-provided duration value would not establish that guarantee.
