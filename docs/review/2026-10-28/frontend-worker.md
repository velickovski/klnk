# Frontend worker — M2/M3

Owner: `/root/quality`. Working tree is shared; root owns manifests, primitives, App integration and API validators. Security owns recorded voice. Platform owns server network/account behavior. This is implementation evidence for this card, not an independent release certification.

## Implemented

- A real React Navigation custom TabRouter mounts only the active panel, links `/workspace/*` and `/join/*`, supports browser history and native incoming URLs, and exposes accessible tabs with unread account updates. The opening screen is owned by root and retains its single Call klnk action.
- A keyed, per-authentication-session data client shares GETs, deduplicates pending reads, retains stable snapshots, fences invalidated responses, refreshes active resources every ten seconds and on return to foreground/online. Mutations are sent once; unknown outcomes trigger readbacks, not automatic mutation replay. The provider is keyed by identity in root App.
- RAM-only drafts and operation IDs survive inactive panels and visits to voice home. Account changes dispose the old cache and drafts. Recipient replies and counterproposal drafts retain their original version. Stale policy edits keep their original expected revision and expose a conflict rather than silently replacing the draft.
- Actual FlatLists render Inbox conversation rows, People connections, Memory records and discriminated Calendar busy/event/reminder rows. Forms and first-run guidance are stable element headers; Inbox notices are its footer. The navigator provides a View for collection routes and a ScrollView only for Settings. This establishes virtualization implementation, not a measured device performance guarantee.
- Inbox uses a focus-managed detail sheet and an entire request card as the tap target. Proposal hashes remain in authorization payloads but no longer appear as user-facing text. Dates use locale-aware formatting.
- Browser date/time inputs and an Expo58-compatible native date/time picker replace raw ISO editing. The browser parser handles nonexistent and repeated DST wall times; ambiguous times require the owner to choose an occurrence. Timezone selection is searchable and defaults to the device zone.
- Private commitments and bounded manual-availability confirmation are explicit owner choices. Confirming availability does not grant delegation. Busy-block retries first read back the same retained interval to avoid duplicating a known committed result; the server does not supply a busy-block idempotence key, so simultaneous independent clients are outside that guarantee.
- Accepted-member links only prefill the invite form. Opening a link never sends or accepts an invitation. Remove/unblock/re-invite controls reflect the server contract. Scoped Memory permissions use checkboxes; capability switches and weekday chips expose their semantic states.
- Progressive setup appears only on subsequent Inbox screens. It guides connecting a person, reviewing manual availability and optionally opening delegation settings, without granting tools or automatic answers/meetings. Advanced delegation fields are collapsed behind a disclosure. Shared semantic badges and AppText are used in owned panels.
