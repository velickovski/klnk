## Security, privacy and operational review

Implemented and tested locally: account/origin response fencing; failed secure credential storage handling; runtime payload validation; owner-first database locking and deleted-account write rejection; durable creation/closure receipts and controller ownership; worker fencing; immutable authorization/context; durable recipient suppression; strict application tools with explicit account grants; encrypted OAuth tokens, session-bound state/PKCE/OIDC, refresh/revoke and cleanup; structural traces without transcripts/arguments; independent restore deletion policy.

The microphone, playback, owner conversation, outbound telephone request and Calendar action remain separate. The local Live browser boundary is intact. A key never grants tools or enables telephone execution. The default permission is off; the Settings permission enables only account lookups, draft preparation and status. External effects from the Live gateway remain disabled. A model/tool result cannot authorize a draft, expand a commitment or establish that a reply was heard.

Content is processed by the backend and configured providers, not end-to-end encrypted. Server resources use authenticated encryption at rest; production key custody and Windows filesystem ACLs require the operator's verified setup. `store:false` requests provider behavior and is not a promise of zero provider retention. Existing per-request transcript settings and background cleanup apply; worker outages can delay cleanup. Voice chat content has a 24-hour cleanup policy. Approved requests retain copied permitted context until their own deletion, as the memory deletion UI explains. Tool argument bindings expire after 24 hours, structural activity after seven days; non-content effect receipts and keyed opt-out records persist for their documented purpose until account deletion. Hash/keyed identifiers remain personal data, not an anonymity claim.

Account deletion revokes credentials and removes personal resources only after active/unknown voice work is reconciled, and retains minimal cleanup jobs with a tombstoned owner. Remote cleanup can be pending/failed; this is not immediate provider erasure. An unresolved no-ID paid receipt can block deletion: provider/operator reconciliation and a reviewed minimal-retention policy are still required before public release. The independent deletion journal must survive separately from backups; a logical dump alone can restore old sessions, leases and deleted content. [The executed quarantine/restore runbook](../operations.md) shows the safe application reconciliation step.
