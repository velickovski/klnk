## What current live evidence establishes

The current validation included real OpenAI WebSocket input/output audio and terminal closure, and an actual Chromium UI → local broker → WebRTC flow using a synthetic microphone. The browser flow received real provider captions, mute/unmute acknowledgements and terminal closure. These are real provider transport results with fictional test audio, not physical-microphone, native-iPhone or whole-product service tests.

The recorded bounded test observed zero delegations and zero external tool calls. Independently, the configured backend declares `tools: []` and `tool_choice: 'none'` in [openai-live.ts](../../apps/server/src/openai-live.ts), lines 106–108. The instruction at line 16 disclaims contacts, calendars, messages, telephone calls and saved memory. A configured key and successful conversation do **not** connect any of those services. See [service boundaries and tracing](04-services-and-tool-tracing.md) and [exact evidence](05-evidence.md).

## Service and product limits that must stay truthful

- Current outbound telephone execution is an allowlisted private pilot. [engine.ts](../../apps/server/src/engine.ts), lines 54–61 and 194–197, checks owner, recipients, provider configuration, retention disclosure, 180-second duration, zero retries and a five-attempt daily limit. Adding an OpenAI key does not change this policy.
- The Google adapter updates an existing event; it is not a full calendar product. It checks recurrence, availability, dates, ETags and an action idempotency marker in [the provider module](../../packages/providers/src/index.ts), lines 331–379.
- Contacts are manual records. An iPhone contact picker is future adapter work; no other-app contact/history harvesting exists.
- Reminder/save-detail/proposed-memory actions are in-app records. [engine.ts](../../apps/server/src/engine.ts), lines 367–377, explicitly does not implement outbound messaging.
- Recipient speech and provider analysis are evidence to review, not new authority or verified agreement. Keep exact-message delegation and avoid adding a redundant confirmation form when the user already gave an unambiguous authorized instruction.
- The UI quality target is exceptional craft, with AA as the web release baseline and stronger contrast where practical. Awards and “10/10” remain aspirations; the [quality matrix](03-tests-and-quality.md) defines observable acceptance.
